5. Justification

For the features, we have agreed to develop the features mentioned above. This is based on the agreement of achieving the main purpose of the software which is a safety driven housing platform with some features included to make the web application more accessible for different stakeholders. The features that are cut is due to the time constraints as it is much complex to implement or it is considered less significant to the web application’s purpose. William’s design plan was chosen for this part as his is the most like what the group has agreed to. So, the specific reasonings for each feature can be analysed from his design plan. 

Examples of features that will be included in our prototype are showcased via the high-level model diagrams and highlight the interactions between the layers/models of the SafeDex system. For examples, the sequence diagram designed by Yong provides an in-depth breakdown of the request and response process of when a user requests to “favourite” a property listing.  The entity-relations diagram, created by Irfan, further showcasing the different connections between components within the SafeDex system.  

We have decided on a combining multiple individual plans for developing the most efficient and reliable technology stack. 

Through a unanimous vote, our frontend shall be developed using React. We all have agreed on using Leaflet.js to implement our map interface and features. We will use Tailwind CSS for styling as justified by Yong and Radix UI for any accessibility technologies, suggested by Isabelle. For data visualisation in a graphical format, we shall use the chart.js library as justified by Sajida. 

For the backend layer, our group has decided to use Springboot and our database will be managed via PostgreSQL. We are all familiar with these systems where justification is shown in most Design Plans. We shall use an external API to source crime data from data.police.uk as recommended by Isabelle and Can. Given our features match William's Individual Design Plan, our system architecture will follow closely to the diagram he has implemented. A detailed explanation of the layers used within the SpringBoot architecture is provided in Sajida’s system architecture model.  

We have decided to split team members and delegate task based on layers of the technology stack into 3-3-1 sub-teams. The Frontend layer shall be developed by Isabelle, Sajida, and Amanda. The Backend layer shall be developed by William, Irfan, and Yong. Finally, the database and data management layer shall be developed by Can.
